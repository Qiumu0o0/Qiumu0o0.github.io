## 计算机网络基础

最近在研究 DPV 问题，作为数专生在计算机网络结构和硬件知识上确实有很多不足，遂开一篇帖子学一学。

### PC（个人电脑）

感觉这个应该暂时不用学，目前的了解够用了。

### 交换机(Swicth)

这里的 switch 可不是任天堂的 switch(乐). 附上一些自己的学习理念：

> 通过例子，尤其是现实例子建立认知，仍然是最重要的东西。如果不行，可以借助网络资源和类比想象建立。但是就我目前的经验来说，自己看得见、摸得着的东西，才是效果最好的。而且最好是在自己已经了解的东西上逐渐拓展，不然新东西太多的话吃不消）大量的例子一定是对的。

鉴于此，我决定从现实场景入手介绍，这应该也是最容易被理解和接收的方式。在初期可以牺牲一些严格性来换取理解，在真正需要足够的严格性的时候，再补上也不迟。在我的观点中，初学阶段，直观和易懂性是大于一切的。（但是避免产生循环论证或者循环定义之类的逻辑混乱，根据我一些模糊的记忆，如果牺牲这两点换取的直观性，大概不是什么好东西）

例子1. 

宿舍有两台电脑，需要相互传输文件。已知网线可以传输文件，所以室友 A, B 决定用一根网线连接两个电脑，这样就可以传输文件了。

![PC1 与 PC2 通过网线直接连接](/images/readings/computer-network-example-1.svg)

例子2. 

考虑新的情况，有室友搬入，电脑变多了。如果还是按照每两台电脑之间连一条网线的方式进行，现在一共需要连6根网线！考虑到网线购买成本，以及更加烦人的布线问题（我自己一个人的插线板我都嫌线太多太乱了lol）

![PC1、PC2、PC3 和 PC4 两两通过网线直接连接，共需六根网线](/images/readings/computer-network-example-2.svg)

有人提出了一个解决方案，每台电脑连接一台公共的机器，然后这台公共机器再转发文件就好了。这个公共连接的机器，就叫做交换机(switch). 

![PC1、PC2、PC3 和 PC4 分别通过网线连接中央交换机](/images/readings/computer-network-example-3.svg)

现在，A 要给 B发送文件，于是它通过网线发送给了交换机（A只连接了交换机一台机器，所以没有发给谁的问题）现在交换机收到了文件，但是它遇到了一个问题：它连接着四个叫「PC」的家伙，怎么才能知道应该发给谁呢？类比一下，就是一个办公室有四个叫张伟的家伙，如果没有工号，当你找张伟的时候，根本不知道找的是哪一个（笑）

解决方法很简单，如果每台电脑有自己的名字，那么 A 在发送文件的时候，附上一条消息，告诉交换机把文件发给 B 就好了。这个电脑的名字，就统称为 **MAC 地址**，就跟张伟的工号一样。一个 MAC 地址的例子是：`A4:5E:60:C2:91:3F`.

> **Tips: 查看自己的电脑的 MAC 地址**
>
> 对于 Windows
> 
> - Win + R 
> - cmd
> - `ipconfig /all`
> - 无线局域网适配器
> - 物理地址

但是，交换机只能看到自己的四个接口，并不知道哪个接口对应的是哪个电脑。怎么办呢？此时，A 发送了一份文件给交换机，并告诉交换机发给 B. 交换机发现这个文件从接口 1 收到的，于是它知道了，接口 1 连接的是电脑 A, 所以它就建立了一个表，**把接口 1 和 A 的 MAC 地址对应起来**。但是此时它仍然不知道 B 接在哪个接口。于是它把这份文件发送到其他三个接口（这个过程叫**泛洪(Flooding)**），B 收到文件后回复了交换机。交换机从接口 2 收到了回复，于是就知道了，2 号接口对应的是 B 的 MAC 地址，于是**记住了这个对应关系**。

就好比你要找张伟1号办一件事情，但是现在有四个门，你你知道有张伟1，2，3，4 号，但是不知道哪个门背后是张伟1号。

> 但是泛洪听起来就非常不安全是不是！

例子3. 

第二天，A 又要给 B 发送一份文件。由于上次交换机已经记住了接口 1，2 和电脑 A，B 的对应关系，于是这次就不用泛洪了，接收到文件之后查找 B 对应的接口，直接发送就行了！

至此，交换机的入门就告一段落，接下来开始学习路由器。

### 路由器(Router)

还是从实际场景入手。

例子1. 

刚刚在同一个宿舍的四个人可以通过交换机相互发送文件，但是现在 C 搬到了另一个寝室，但是没关系，把这两个寝室的交换机之间拉一根网线连起来就好了。

![寝室 1 与寝室 2 的交换机通过网线连接，四台电脑分别接入所在寝室的交换机](/images/readings/computer-network-router-example-1.svg)

例子2.

现在 D 搬到了另一栋楼，这下可麻烦了！我们现在的网线不够长，没有办法连接两栋楼之间的交换机。不过先跑题一下，A 最近在学图论，他发现这个宿舍的电脑的连接关系，可以看成一个图。B 在学习计算机网络基础，他告诉 A, 这个图也可以看成是一个**网络(Network)**。

这时候有人拿出了一个更大的机器，可以连接两个不同楼的交换机，这个机器就叫**路由器(Router)**.（其实这里本质还是靠网线连接，不过这里的网线更厉害，连接距离更远，称为**光纤**）对于这样的连接，我们通常称为路由器连接了不同的网络。

![路由器通过光纤连接两栋楼中的两个网络](/images/readings/computer-network-router-example-2.svg)

例子2. 

现在 A 想要给 D 发送文件，A 知道自己的 **IP 地址**（这里可以先视为住址，比如你家在xx省xx市xx区xx小区xx号楼x-x）：`192.168.1.10`, 也知道 D 的 IP 地址：`192.168.2.11`，发现第三位数字不同，于是知道 D 和自己不在同一栋楼。所以，A 只好把自己的请求发给交换机，再让交换机发给路由器。不过，交换机不知道路由器的 MAC 地址，所以需要 A 先知道这个信息，再告诉交换机。但是，A 知道路由器的 IP 地址，所以 A 在网络中询问：「谁是 192.168.1.1？请告诉我你的 MAC 地址！」路由器回复了自己的 MAC 地址。（这个通过 IP 地址查找 MAC 地址过程就叫 **ARP(Address Resolution Protocol)**, 即地址解析协议，通过根据 IP 地址，查找对应的 MAC 地址）

现在 A 把 D 的 IP 地址和路由器的 MAC 地址都发给了交换机，交换机再把消息发给路由器。路由器查看了 D 的 IP 地址，发现 D 所在的楼在另一个接口对应的位置。路由器在这个网络中做了一次 ARP, 得到了 D 的 MAC 地址，于是把 D 的 MAC 地址和要发送的文件告诉了 D 所在网络的交换机。交换机通过 D 的 MAC 地址，就可以把文件传输给 D 了。

| 对比维度 | 交换机（Switch） | 路由器（Router） |
| --- | --- | --- |
| 主要作用 | 连接同一网络中的设备，并在设备之间转发数据 | 连接不同网络，并在网络之间转发数据 |
| 转发依据 | MAC 地址 | IP 地址 |
| 典型工作范围 | 一个局域网内部 | 不同网络之间 |
| 在本文例子中 | 连接同一寝室或楼内的电脑 | 连接两栋楼中的两个网络 |
