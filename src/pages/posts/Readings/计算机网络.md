## 计算机网络基础

最近在研究 DPV 问题，作为数专生在计算机网络结构和硬件知识上确实有很多不足，遂开一篇帖子学一学。

### PC（个人电脑）

感觉这个应该暂时不用学，目前的了解够用了。

### 交换机(Swicth)

这里的 switch 可不是任天堂的 switch(乐). 附上一些自己的学习理念：

> 通过例子，尤其是现实例子建立认知，仍然是最重要的东西。如果不行，可以借助网络资源和类比想象建立。但是就我目前的经验来说，自己看得见、摸得着的东西，才是效果最好的。而且最好是在自己已经了解的东西上逐渐拓展，不然新东西太多的话吃不消）大量的例子一定是对的。

鉴于此，我决定从现实场景入手介绍，这应该也是最容易被理解和接收的方式。在初期可以牺牲一些严格性来换取理解，在真正需要足够的严格性的时候，再补上也不迟。在我的观点中，初学阶段，直观和易懂性是大于一切的。（但是避免产生循环论证或者循环定义之类的逻辑混乱，根据我一些模糊的记忆，如果牺牲这两点换取的直观性，大概不是什么好东西）

例子1. 

宿舍有两台电脑，需要相互传输文件。已知网线可以传输文件，所以室友 A, B 决定用一根网线连接两个电脑，这样就可以传输文件了。

![PC1 与 PC2 通过网线直接连接](/images/readings/computer-network-example-1.svg)

例子2. 

考虑新的情况，有室友搬入，电脑变多了。如果还是按照每两台电脑之间连一条网线的方式进行，现在一共需要连6根网线！考虑到网线购买成本，以及更加烦人的布线问题（我自己一个人的插线板我都嫌线太多太乱了lol）

![PC1、PC2、PC3 和 PC4 两两通过网线直接连接，共需六根网线](/images/readings/computer-network-example-2.svg)

有人提出了一个解决方案，每台电脑连接一台公共的机器，然后这台公共机器再转发文件就好了。这个公共连接的机器，就叫做交换机(switch). 

![PC1、PC2、PC3 和 PC4 分别通过网线连接中央交换机](/images/readings/computer-network-example-3.svg)

现在，A 要给 B发送文件，于是它通过网线发送给了交换机（A只连接了交换机一台机器，所以没有发给谁的问题）现在交换机收到了文件，但是它遇到了一个问题：它连接着四个叫「PC」的家伙，怎么才能知道应该发给谁呢？类比一下，就是一个办公室有四个叫张伟的家伙，如果没有工号，当你找张伟的时候，根本不知道找的是哪一个（笑）

解决方法很简单，如果每台电脑有自己的名字，那么 A 在发送文件的时候，附上一条消息，告诉交换机把文件发给 B 就好了。这个电脑的名字，就统称为 **MAC 地址**，就跟张伟的工号一样。一个 MAC 地址的例子是：`A4:5E:60:C2:91:3F`.

> **Tips: 查看自己的电脑的 MAC 地址**
>
> 对于 Windows
> 
> - Win + R 
> - cmd
> - `ipconfig /all`
> - 无线局域网适配器
> - 物理地址

但是，交换机只能看到自己的四个接口，并不知道哪个接口对应的是哪个电脑。怎么办呢？此时，A 发送了一份文件给交换机，并告诉交换机发给 B. 交换机发现这个文件从接口 1 收到的，于是它知道了，接口 1 连接的是电脑 A, 所以它就建立了一个表，**把接口 1 和 A 的 MAC 地址对应起来**。但是此时它仍然不知道 B 接在哪个接口。于是它把这份文件发送到其他三个接口（这个过程叫**泛洪(Flooding)**），B 收到文件后回复了交换机。交换机从接口 2 收到了回复，于是就知道了，2 号接口对应的是 B 的 MAC 地址，于是**记住了这个对应关系**。

就好比你要找张伟1号办一件事情，但是现在有四个门，你你知道有张伟1，2，3，4 号，但是不知道哪个门背后是张伟1号。

> 但是泛洪听起来就非常不安全是不是！

例子3. 

第二天，A 又要给 B 发送一份文件。由于上次交换机已经记住了接口 1，2 和电脑 A，B 的对应关系，于是这次就不用泛洪了，接收到文件之后查找 B 对应的接口，直接发送就行了！

至此，交换机的入门就告一段落，接下来开始学习路由器。

### 路由器(Router)

还是从实际场景入手。

例子1. 

刚刚在同一个宿舍的四个人可以通过交换机相互发送文件，但是现在 C 搬到了另一个寝室，但是没关系，把这两个寝室的交换机之间拉一根网线连起来就好了。

![寝室 1 与寝室 2 的交换机通过网线连接，四台电脑分别接入所在寝室的交换机](/images/readings/computer-network-router-example-1.svg)

例子2.

现在 D 搬到了另一栋楼，这下可麻烦了！我们现在的网线不够长，没有办法连接两栋楼之间的交换机。不过先跑题一下，A 最近在学图论，他发现这个宿舍的电脑的连接关系，可以看成一个图。B 在学习计算机网络基础，他告诉 A, 这个图也可以看成是一个**网络(Network)**。

这时候有人拿出了一个更大的机器，可以连接两个不同楼的交换机，这个机器就叫**路由器(Router)**.（其实这里本质还是靠网线连接，不过这里的网线更厉害，连接距离更远，称为**光纤**）对于这样的连接，我们通常称为路由器连接了不同的网络。

![路由器通过光纤连接两栋楼中的两个网络](/images/readings/computer-network-router-example-2.svg)

例子2. 

现在 A 想要给 D 发送文件，A 知道自己的 **IP 地址**（这里可以先视为住址，比如你家在xx省xx市xx区xx小区xx号楼x-x）：`192.168.1.10`, 也知道 D 的 IP 地址：`192.168.2.11`，发现第三位数字不同，于是知道 D 和自己不在同一栋楼。所以，A 只好把自己的请求发给交换机，再让交换机发给路由器。不过，交换机不知道路由器的 MAC 地址，所以需要 A 先知道这个信息，再告诉交换机。但是，A 知道路由器的 IP 地址，所以 A 在网络中询问：「谁是 192.168.1.1？请告诉我你的 MAC 地址！」路由器回复了自己的 MAC 地址。（这个通过 IP 地址查找 MAC 地址过程就叫 **ARP(Address Resolution Protocol)**, 即地址解析协议，通过根据 IP 地址，查找对应的 MAC 地址）

现在 A 把 D 的 IP 地址和路由器的 MAC 地址都发给了交换机，交换机再把消息发给路由器。路由器查看了 D 的 IP 地址，发现 D 所在的楼在另一个接口对应的位置。路由器在这个网络中做了一次 ARP, 得到了 D 的 MAC 地址，于是把 D 的 MAC 地址和要发送的文件告诉了 D 所在网络的交换机。交换机通过 D 的 MAC 地址，就可以把文件传输给 D 了。

| 对比维度     | 交换机（Switch）                           | 路由器（Router）                   |
| ------------ | ------------------------------------------ | ---------------------------------- |
| 主要作用     | 连接同一网络中的设备，并在设备之间转发数据 | 连接不同网络，并在网络之间转发数据 |
| 转发依据     | MAC 地址                                   | IP 地址                            |
| 典型工作范围 | 一个局域网内部                             | 不同网络之间                       |
| 在本文例子中 | 连接同一寝室或楼内的电脑                   | 连接两栋楼中的两个网络             |

### 防火墙(Firewall)

同样的，我们还是用例子来引入：

例子1. 假设有一个学生和一个老师，学生只能访问公开网站，比如学校的主页。老师除了可以访问学校主页，还可以访问成绩数据库。这里阻止学生访问成绩数据库，而允许老师访问该数据库的东西，就是**防火墙**。

总的来说，防火墙可以是一台独立硬件，也可以是运行在电脑或者服务器上的软件。**它根据预先设定的规则，允许或者阻止网络通信。**那么，其中一个关键任务就是**区分不同的访问者**，其中最简单的方式就是使用不同的登录账号。不同的账号在注册的时候被赋予了不同的身份标记，在这个例子中，身份标记就是学生和老师。

例子2. 假设学生没有登录账号，尝试直接访问成绩数据库。此时，防火墙无法确认该访客的身份，于是按照相应的规则，会拒绝这次访问。

例子3. 这天早上，老师来到办公室使用电脑并登录账号，访问数据库。这台电脑的 IP 地址是 `192.168.1.10`. 但是当晚老师回到家后使用家中电脑登录账号（此时电脑的 IP 地址可能是 `192.168.2.10`），再次访问数据库的时候，访问被拒绝了。

> IP 地址是分配给电脑的网络连接的，并非电脑的永久编号。当一台电脑同时连接 Wi-Fi 和网线的时候，可能会有两个 IP 地址。所以 IP 地址可以看成电脑在当前网络中的地址。所以这个例子中，是否使用同一台电脑并不是问题的关键，关键是在学校的时候连接的是校园网络，回到家后连接的是家中的 Wi-Fi. 如果老师在学校使用手机热点等其他网络，按照「只能校园网络 + 教师账号访问成绩数据库」的规则，也是无法访问的。

这里引出一个概念：**来源地址**(Source Address), 即发出访问请求数据的来源。不过同时，防火墙也要判断该访问请求的目标，即学校主页（IP 地址 `192.168.1.20`）或者成绩数据库（`192.168.1.30`）. 那么，**这里的意思是网站也有 IP 地址吗？**其实并非如此，这里说的 IP 地址，实际上是指**提供网站服务的服务器的 IP 地址**，而网站本身是不存在 IP 地址的概念的。这里可以先把服务器看作一台电脑，它可以被连接到网络中，因此具有 IP 地址。

<!-- 这里的服务器，一定要在校园网下吗？但是那些云服务器好像可以相隔万里提供服务。不过这个问题对于我们目前的阶段来说有点超前，可以先搁置一下。 -->

也就是说，对于一次访问，防火墙需要判断至少三个东西：身份、来源 IP 以及目标 IP. 这三个数据可以看作输入，对于每一种输入，防火墙会返回允许/拒绝的结果，这样的一个函数就是防火墙的**规则**。

例子4. 下面来看这个防火墙的规则：

| 规则 | 身份 | 来源 IP | 目标 IP | 结果 |
| ---- | ---- | ------- | ------- | ---- |
| 1    | 老师 | 任意    | 数据库  | 允许 |
| 2    | 任意 | 任意    | 数据库  | 拒绝 |

现在老师从校园网访问数据库，那么这次访问同时满足这两条规则，但是却返回了不同的结果。那么这里就要用到另一个概念：**规则的优先级**。在进行规则匹配的时候，采用从前到后的方式，一旦有匹配的规则就停止。

从这里可以看出，防火墙的规则函数的编写并不是一个划分。至于这样设计的原因，是考虑到规则的简洁性的需求。如果按照划分的方式去制定规则，可能需要大量的规则。但是如果使用带有优先级的可以允许重叠的规则方式，往往可以大幅度简化规则。

例子5. 从之前对服务器的介绍可以看出，一台服务器可以提供多个服务，比如学校主页和成绩查询系统。这些不同服务具有相同的 IP 地址，那么，**怎么区分不同的服务呢**？此时，就要使用**端口号**(Port Number)了，目的是在同一个服务器中区分不同的服务。比如，HTTP 网站服务的端口号通常是 80，而 HTTPS 网站服务的端口号通常是 443.

类比服务器，由于我们之前说过，服务器可以看成是一台电脑，所以电脑也有自己的端口，不同的端口可以区分不同的**网络通信**或者**服务**（比如 HTTP 和 HTTPS 就是不同的网页服务，而 Chrome 请求学校主页，以及微信接受消息，就是一次网络通信。微信和 Chrome 的端口号可能是 52001 和 52002），操作系统利用不同的端口号区分电脑上的不同网络通信。

如果现在用电脑上的 Chrome 浏览器访问学校主页，那么电脑会使用一个临时端口，例如 `52001`, 而学校服务器可能会使用 `443` 端口提供 HTTPS 服务。这次通信就可以简写为：

$$
\underbrace{\mathtt{192.168.1.10:52001}}_{\text{Chrome 客户端}}
\xrightarrow{\text{HTTPS 请求}}
\underbrace{\mathtt{192.168.1.20:443}}_{\text{学校服务器}}
$$

其中 `52001` 为源端口，`443` 为目标端口。所以在编写防火墙规则的时候，端口号也非常重要，因为它决定了哪些服务可以被访问。

例子6. 比如 A 要给 B 写信，则他需要在信封写出寄信人和收信人，以及把信纸放入信封中。这样，邮递员才知道，应该把信给谁，B 也才知道谁寄出了这封信。如果这套通信系统没有一个被寄信人、收信人和邮递员共同知道的规则（或者说格式），这个过程就无法进行。这里的规则和格式，就是**通信协议**(Protocol)，即通信双方约定的数据交换的规则。

例子7. 刚刚 A 给 B 寄了一封普通信件，邮递员按照规定投递到邮筒中即可。之后，A 又需要给 B 寄一封重要信件，因此他希望 B 能当面签收。此时，邮递员就不能把信件投进邮筒了，而是需要联系到 B 让他当面签收。显然，由于需求的不同，这两次邮寄使用了不同的规则。计算机通信也是类似的，针对不同的场景，我们需要制定不同的通信协议。

下面，我们介绍计算机网络中两种常见的通信协议：TCP 和 UDP.

简单来说，TCP(Transmission Control Protocol) 是一种提供可靠数据传输的通信协议。比如例子7中，B 需要当面签收，在 TCP 中，就是要求接收方发送确认信息(ACK, i.e. Acknowledgment), 让发送方知道数据已经收到。但是，如果超过一定时间期限后仍然没有收到 ACK, A 就会重新发送数据，直到收到确认或者达到重传限制。这里重新发送数据的过程就叫做**重传**(Retransmission). **TCP 通过确认和重传机制，来提高数据传输的可靠性**。

UDP(User Datagram Protocol) 和 TCP 不同，TCP 重视传输的可靠性，而 UDP 重视传输的及时性。

例子8. A 正在和 B 视频通话，如果视频传输的时候丢失了一帧，手机等设备会直接播放下一帧，而不是等待那一帧的传输。这种传输方式就是 UDP.

例子9. 回到刚刚学校的场景。假设学校的服务器提供两个不同的服务：学校主页和实时视频直播。学校主页通常采用 TCP 协议，而视频直播通常采用 UDP 协议。

至此我们知道，防火墙不仅检查 IP 地址、端口，还可以检查传输协议。

### 服务器

例子1. 学校需要保存所有学生的成绩，并允许老师查询、修改成绩。如果每位老师的电脑都单独保存一份成绩，更新和管理会非常麻烦。于是学校准备了一台专门负责保存成绩、响应查询请求的电脑。这台电脑就可以称为**服务器**(Server). 

现在，老师需要查询成绩。于是，老师打开了自己的电脑中的浏览器，输入学校成绩系统的网址进行查询。即老师的电脑向服务器发送了查询请求，服务器收到请求后，查询保存的成绩，然后把查询结果返回给老师的电脑。在这个过程中，老师的电脑就称为**客户端(Client)**, 即发起请求和使用服务的电脑。

假设服务器的 IP 地址是 `192.168.1.20`, 老师需要知道这个地址，才能向服务器发送请求。但是，直接记忆 IP 地址很麻烦，所以学校就给服务器中的成绩系统服务设置了一个**域名**(Domain Name)，比如 `grade.school.edu`. 简单来说，域名就是方便人们记忆的服务器地址名称。但是由于域名不是 IP 地址，所以电脑需要从输入的域名，查找相应的 IP 地址。

由此，我们可以引出 DNS(Domain Name System). DNS 可以看成是一个域名查询系统，其中包含若干数据库，存储着域名和 IP 地址的对应关系。所以，在电脑接收到输入的域名之后，就会向**预先配置好的 DNS 服务器**发送查询请求，得到对应的 IP 地址。

这里，老师向服务器发送的**请求**(Request)的具体操作要求是**查询**(Query)。服务器找到记录后，返回相应的信息，比如「学号001，数学成绩95分。」这个返回结果称为**响应**(Response). 

$$
\begin{aligned}
\text{客户端}
&\xrightarrow{\text{请求（Request）}}
\text{服务器}, \\
\text{客户端}
&\xleftarrow{\text{响应（Response）}}
\text{服务器}.
\end{aligned}
$$

### 数据包（Packet）

例子1. A 要通过微信给 B 发送一张图片。但是实际上，被发送的是一个数据包。这个数据包通常由两部分组成：头部（Header）和载荷（Payload）. 头部记录传输所需的信息，包括源IP, 目标IP, 源端口，目标端口，以及通信协议。载荷则是真正被发送的数据。

> 而回看之前服务器的例子，一次查询请求也是一次数据传输，所以这个查询也会被组织成数据包，其中头部会记录sip, dip, sp, dp 和 pr 等信息，而 payload 中则会携带具体的请求内容，比如「查询学号001的数学成绩。」服务器的回复，也是一个数据包。

下面借助这个例子，完成一次完整的网络数据传输流程。在 A 的电脑上，微信收到发送图片的命令之后，会把图片给电脑的操作系统，然后操作系统会填写数据包的头部和载荷。操作系统判断 sip 和 dip 不在同一网络中，于是决定把数据交给路由器。于是，电脑 A 借助 ARP 查询路由器的 MAC 地址，获得 MAC 地址之后，A 将数据包交给交换机，然后交换机根据目标 MAC 地址，将数据转发给路由器。

路由器检查 dip 之后，找到相应网络对应的接口。随后，路由器通过 ARP 或者 B 的 MAC 地址，再将数据发送给 B 所在网络的交换机。交换机通过 MAC 地址，把数据包交给 B. 最后，B 通过数据包中的 dp 等信息，把数据交给对应的服务。

![数据包从微信 A 经操作系统、交换机和路由器传输到微信 B 的完整路径](/images/readings/computer-network-packet-transmission.svg)

这里有一个小问题，就是 A 是如何知道路由器的 IP 地址的？事实上，当电脑再连接网络的时候，会获得一个**默认网关**(Default Gateway)的 IP 地址。这个地址通常就是路由器在当前网络中的 IP. 

另一个小问题是，A 是如何获得 B 的 IP 地址的？事实上，之前对于访问成绩数据库的例子，dip 是一个公开的信息。而对于微信通信来说，微信服务器可以通过 B 的账号查询 B 的 IP 信息，然后再把这个信息设法交给 A 的电脑。 

### 子网掩码（Subnet Mask）

下面回到这个问题：**两台电脑是否属于同一个网络**？假设 A 的 IP：`192.168.1.10`, 子网掩码：`255.255.255.0`. 子网掩码的作用是告诉电脑，IP 地址中哪些部分表示网络，哪些部分表示设备。比如这个子网掩码，就表示前三组数字属于网络，最后一组属于设备。因此，对于 B 的 IP `192.168.1.20`, A 可以知道 B 和自己在同一网络中。通常，双方会使用相同的子网掩码，但是在特殊情况下，当双方使用不同的子网掩码，可能会出现不对称的判断，即 A 认为 B 在自己所处的网络中，而 B 认为 A 不在自己所处的网络中。

### 路由表（Routing Table）

路由器知道了 dip 之后，需要选择对应的接口来发送数据包。

例子1. 

| 目标网络（Destination） | 出口接口（Interface） |
| --- | --- |
| `192.168.1.0/24` | 接口 1 |
| `192.168.2.0/24` | 接口 2 |
| `192.168.3.0/24` | 接口 3 |

现在，路由器收到一个目标 IP 地址为 `192.168.2.11` 的数据包。查询路由表后，路由器发现该地址与目标网络 `192.168.2.0/24` 匹配，因此选择接口 2 转发这个数据包。

例子2. 

| 目标网络（Destination） | 出口接口（Interface） |
| --- | --- |
| `192.168.0.0/16` | 接口 1 |
| `192.168.2.0/24` | 接口 2 |

现在路由器收到一个 `DIP = 192.168.2.11` 的数据包，查找路由表，发现它同时匹配两个规则。这里 `/16`：覆盖 `192.168.x.x`，`/24`：覆盖 `192.168.2.x`。在这种情况下，路由器选择接口2，因为 `/24` 的范围更小更具体。这样的规则匹配模式，就叫做 **最长前缀匹配**(Longest Prefix Match).

例子3.  

| 目标网络（Destination） | 出口接口（Interface） |
| --- | --- |
| `192.168.1.0/24` | 接口 1 |
| `192.168.2.0/24` | 接口 2 |

现在路由器收到一个 `DIP = 192.168.3.10` 的数据包，它无法匹配任何规则。这时候，路由器可能会使用一条特殊规则：**默认路由**(Default Route). 默认路由通写为：`0.0.0.0/0`, 它表示匹配所有 IPv4 地址。现在看加上了默认路由的路由表：

| 目标网络（Destination） | 出口接口（Interface） | 说明 |
| --- | --- | --- |
| `192.168.1.0/24` | 接口 1 | 直连网络 |
| `192.168.2.0/24` | 接口 2 | 直连网络 |
| `0.0.0.0/0` | 接口 3 | 默认路由 |

因此对于刚刚那个 IP 地址，路由器会选择从接口3转发。

例子4. 有时候，路由器 R1 不能直接连接到目标网络，需要经过另一台路由器 R2 才行。R2 与 R1 相连的网络接口上的 IP 地址被称为**下一跳**(Next Hop Address). 这里下一跳的 IP 可能是 `10.0.0.2`.
