## 中文版

本文根据关于 Discrete Event Systems 中 Opacity 的手写阅读笔记整理，所参考的综述由 [Jacob et al.](https://doi.org/10.1016/j.arcontrol.2016.04.015) 撰写，发表于 *Annual Reviews in Control*。笔记涉及 Models、Validation 和 Quantification。

### 研究背景

Network Communication 与 Online Services 中的 **Security** 和 **Privacy** 需求推动了 Information Flow 研究，也促使研究者发展相关理论，以设计满足 Opacity 的系统。相关概念包括 Anonymity、Non-interference、Secrecy、Privacy、Security 和 Opacity。

Opacity 用于描述系统如何保护 Secret：**对于每一种 Secret Behavior，都存在至少一种在 Intruder 看来完全相同的 Non-secret Behavior。** 因此，Intruder 无法仅凭 Observation 断定 Secret 已经发生。

这里假设 Intruder 完全了解系统的 Model，但对系统行为仅具有 Partial Observability，并根据获得的 Observation 估计系统的实际情况。当 Secret Behavior 与 Non-secret Behavior 产生相同的 Observation 时，后者便为前者提供了掩护。

笔记记录的综述内容包括：

- **Logical Models** 中的 Opacity Validation。
- **Probabilistic Models** 中的 **Opacity Quantification** 与 Information Leakage 风险。
- Decidability 和 Complexity 结果。
- 已有 Verification Tools，以及工具是否支持 Quantification 的问题。
- Discrete Event Systems 中的应用与未来研究方向。

Logical Models 通常回答系统是否满足 Opacity；Probabilistic Models 则用于衡量 **Information Leakage 风险**。

### 基本记号

下文采用手稿中的 Automaton 记号：

$$
G=(X,E,f,X_0).
$$

- $X$：State Set。
- $E$：Event Set。
- $f$：Transition Function，同时定义其在 Event String 上的扩展。
- $X_0\subseteq X$：可能的 Initial State Set。
- $\mathcal L(G,i)$：从 State $i$ 出发能够发生的 Event String 集合。
- $\mathcal L(G,X_0)$：从某个 Initial State 出发能够发生的 Event String 集合。
- $E_o\subseteq E$：Observable Event Set。
- $P:E^*\to E_o^*$：Natural Projection，用于删除 Unobservable Event。

若 $P(t)=P(t')$，Intruder 就无法通过 Observation 区分 Event String $t$ 与 $t'$。符号 $\varepsilon$ 表示 Empty String。

Opacity 的定义主要分为 **Language-Based Opacity** 和 **State-Based Opacity** 两类。

### Language-Based Opacity

Language-Based Opacity（LBO）也称 Trace-Based Opacity，以一组 Event String 表示 Secret，而非以单个 State 表示。

笔记提到了 [Badouel et al. (2007)](https://doi.org/10.1007/s10626-007-0020-5)、[Dubreil et al. (2008)](https://doi.org/10.1109/WODES.2008.4605918) 和 [Lin (2011)](https://doi.org/10.1016/j.automatica.2011.01.002) 的研究。Lin 的表述使用两个 Sublanguage。

设

$$
L_S\subseteq\mathcal L(G,X_0),\qquad
L_{NS}\subseteq\mathcal L(G,X_0)
$$

分别表示 Secret Language 和 Non-secret Language。

#### Strong Opacity

系统满足 Strong LBO，当且仅当

$$
\forall t\in L_S,\quad
\exists t'\in L_{NS}:\quad P(t)=P(t').
$$

等价地，

$$
L_S\subseteq P^{-1}\bigl(P(L_{NS})\bigr),
$$

也可写成

$$
P(L_S)\subseteq P(L_{NS}).
$$

也就是说，每个 Secret String 都有一个产生相同 Observation 的 Non-secret String。通常，未作特别说明的 LBO 指 Strong Opacity。

#### Weak Opacity

系统满足 Weak LBO，当且仅当

$$
\exists t\in L_S,\quad
\exists t'\in L_{NS}:\quad P(t)=P(t').
$$

等价地，

$$
L_S\cap P^{-1}\bigl(P(L_{NS})\bigr)\ne\varnothing.
$$

Weak Opacity 只要求至少一个 Secret String 存在 Non-secret String 作为掩护，并不保证所有 Secret Behavior 都受到保护。

#### No Opacity

手稿将以下情形称为 No Opacity：

$$
L_S\cap P^{-1}\bigl(P(L_{NS})\bigr)=\varnothing.
$$

此时，任何 Secret String 都无法找到产生相同 Observation 的 Non-secret String。

#### 例子：Secret Language 的选择会影响结论

手稿中的 Automaton 如下，Initial State 为 $0$：

![Automaton：Initial State 为 0，包含 a、b、d Transitions 和 State 2 上的 c Self-loop。](/opacity-lbo-automaton.svg)

取 $E_o=\{a,b,c\}$，因此 $d$ 为 Unobservable Event。

当

$$
L_S=\{abd\},\qquad
L_{NS}=\{abc^nd\mid n\ge0\}\cup\{adb\},
$$

有

$$
P(abd)=ab=P(adb).
$$

由于 Secret String $abd$ 有 Non-secret String $adb$ 作为掩护，因此满足 LBO。

如果改为

$$
L_S=\{abcd\},\qquad
L_{NS}=\{adb,abd\}\cup\{abc^nd\mid n\ge2\},
$$

则

$$
P(abcd)=abc,\qquad P(adb)=P(abd)=ab.
$$

其余 Non-secret String 产生的 Observation 为 $abc^n$，其中 $n\ge2$，也不同于 $abc$。因此不满足 LBO。

即使 Automaton 与 Observation Projection 相同，选择不同的 Secret Language 和 Non-secret Language，也可能得到不同的 Opacity 结论。

> 手稿第 4 页第二个例子中，Non-secret Language 的写法与后续 Observation 计算不一致。这里依据后续的 $abcc^*$ 计算，将相关 Event String 限定为至少包含两个 $c$。如果 Non-secret Language 包含 $abcd$，该串就能为自身提供掩护，原稿预期的反例便不成立。

### State-Based Opacity

State-Based Opacity（SBO）以 State、Initial State，或 Initial State 与 Final State 的组合表示 Secret。

#### Current-State Opacity

Current-State Opacity（CSO）用于隐藏系统当前是否处于 Secret State。

设 $X_S\subseteq X$ 和 $X_{NS}\subseteq X$ 分别为 Secret State Set 与 Non-secret State Set。每条到达 Secret State 的 Execution，都必须有一条产生相同 Observation、但到达 Non-secret State 的 Execution 与之对应：

$$
\begin{aligned}
&\forall i\in X_0,\ \forall t\in\mathcal L(G,i),\quad
f(i,t)\in X_S\\
&\qquad\Longrightarrow
\exists j\in X_0,\ \exists t'\in\mathcal L(G,j):\\
&\qquad\qquad f(j,t')\in X_{NS}\ \land\ P(t)=P(t').
\end{aligned}
$$

作为掩护的 Execution 可以从另一个 Initial State 出发，但必须产生相同的 Observation，并结束于 Non-secret State。

手稿还提到 **always opacity / total opacity**：对于所考虑的一组 Run，每个访问到的 State 都应满足相应的 Current-State Opacity。原稿没有进一步给出形式化定义。

**例子。** 以下 Automaton 的 Initial State 为 $0$：

![Automaton：Initial State 0 分别经 a、b 到达 State 3，经 c、b 到达 State 4。](/opacity-cso-automaton.svg)

令 $X_S=\{3\}$，其余 State 为 Non-secret State。

- 若 $E_o=\{b\}$，则 $P(ab)=P(cb)=b$。到达 Secret State $3$ 的 Execution 与到达 Non-secret State $4$ 的 Execution 无法通过 Observation 区分，因此满足 CSO。
- 若 $E_o=\{a,b\}$，则 Observation $ab$ 足以确定系统到达了 Secret State $3$，因此不满足 CSO。

可见，Opacity 也取决于 Intruder 的 Observability。

#### Initial-State Opacity

Initial-State Opacity（ISO）用于隐藏系统是否从 Secret State 开始运行。

这里，$X_S$ 与 $X_{NS}$ 分别表示需要比较的 Secret Initial State Set 和 Non-secret Initial State Set。ISO 的定义为

$$
\forall i\in X_S,\ \forall t\in\mathcal L(G,i),\quad
\exists j\in X_{NS},\ \exists t'\in\mathcal L(G,j):\quad
P(t)=P(t').
$$

从 Secret Initial State 出发产生的每一种 Observation，都必须也能从某个 Non-secret Initial State 出发产生。

**例子。** 手稿中的 Automaton 如下，其中 $\tau$ 为 Unobservable Event，$E_o=\{a,b\}$：

![Initial-State Opacity Automaton：State 0 上有 a Self-loop，τ 为 Unobservable Event；各 Transitions 与手稿一致。](/opacity-iso-automaton.svg)

若 $2$ 为 Secret Initial State，且 $0$ 是允许的 Non-secret Initial State，则从 $2$ 出发的任意 Execution 都有掩护：从 $0$ 出发，先通过 Unobservable Event $\tau$ 到达 $2$，再沿同一 Execution 继续。两者产生相同的 Observation，因此对于手稿比较的 Initial State Set，系统满足 ISO。

若改为将 $0$ 设为 Secret Initial State，则 Observation $aa$ 只能由从 $0$ 出发的 Execution 产生。其余 State 必须经过 Observable Event $b$，才能再次产生 $a$，因而无法产生连续两个 $a$ 的 Observation。当其他 State 为 Non-secret Initial State 时，系统不满足 ISO。

> 此例比较了多个可能的 Initial State。不能将图中指向 $0$ 的 Initial Arrow 理解为仅允许 $0$ 作为 Initial State；这种理解会排除笔记中使用的、从 $2$ 出发的 Secret Execution。

#### Initial-and-Final-State Opacity

Initial-and-Final-State Opacity（IFO）用于隐藏 Initial State 与 Final State 的组合信息。手稿将这一概念关联到 [Wu and Lafortune (2013)](https://doi.org/10.1007/s10626-012-0145-z)。

设 Secret State Pair Set 与 Non-secret State Pair Set 分别为

$$
X_{SP}\subseteq X_0\times X,\qquad
X_{NSP}\subseteq X_0\times X.
$$

定义为

$$
\begin{aligned}
&\forall (x_0,x_f)\in X_{SP},\quad
\forall t\in\mathcal L(G,x_0),\quad f(x_0,t)=x_f\\
&\qquad\Longrightarrow
\exists (x_0',x_f')\in X_{NSP},\quad
\exists t'\in\mathcal L(G,x_0'):\\
&\qquad\qquad f(x_0',t')=x_f'\ \land\ P(t)=P(t').
\end{aligned}
$$

作为掩护的 Event String $t'$ 必须从对应的 Initial State $x_0'$ 出发。原稿在这一位置漏写了撇号，整理时已修正。

ISO 和 CSO 可以视为 IFO 的特殊情形：

- 若 $X_{SP}=X_S\times X$，$X_{NSP}=X_{NS}\times X$，其中 $X_S,X_{NS}\subseteq X_0$，只限制 Initial State，得到 ISO。
- 若 $X_{SP}=X_0\times X_S$，$X_{NSP}=X_0\times X_{NS}$，只限制 Final State，得到 CSO。

### Verification 与保障 Opacity

给定系统 $G$、Secret 和 Intruder 获取 Observation 的方式，需要回答两个问题：**系统是否满足所要求的 Opacity？若不满足，如何使其满足？**

手稿列出了三种主要方法：

| 方法 | 目的 | 手稿中的描述 |
| --- | --- | --- |
| Verification | 判断系统是否满足 Opacity | 对 Opacity 性质进行 Model Checking |
| Supervisory Control Theory（SCT） | 限制系统行为以保护 Secret | 通过约束系统允许发生的行为维持 Opacity |
| Enforcement | 在 Observation 的输入与输出环节保障 Opacity | 手稿写到“输入 Observable Events，输出修改后的信息”后中断 |

#### 4.1 Verification

Opacity Verification $\iff$ **Universality Problem**，这一结论由 [Cassez, Dubreil & Marchand, 2012](https://doi.org/10.1007/s10703-012-0141-9) 给出。

此外，通过**对 Opacity Properties 进行编码**，可以将求解归约为**经典的 Model-Checking 方法与工具**。

#### 4.2 SCT

核心问题是构造特定类型的 **Supervisor**。Supervisor 用于控制 Controllable Events，以保护 Secret。

这篇综述没有给出 Mathematical Definition。

#### 4.3 Enforcement（Non-intrusive）

主要有三种方法：

- 从输出中删除 Event 的出现；
- 向输出中添加 Event；
- **延迟**输出。

## English Version

This article is organized from handwritten reading notes on a review of Opacity in Discrete Event Systems by [Jacob et al.](https://doi.org/10.1016/j.arcontrol.2016.04.015), published in *Annual Reviews in Control*. The notes concern models, validation, and quantification. 

### Background

**Security** and **privacy** concerns in network communication and online services motivate research on information flow, and some theories are proposed to **design opaque system**. Related concepts include anonymity, non-interference, secrecy, privacy, security, and opacity.

Opacity describes the protection of secrets: **every secret behavior has a non-secret behavior that looks identical to the intruder.** Consequently, the intruder cannot conclude from the observation alone that the secret has occurred.

The intruder is assumed to know the complete system model but to have only partial observability of its behavior. It constructs estimates of the system from observations. When secret and non-secret behaviors produce the same observation, the non-secret behavior provides a cover for the secret.

The review topics recorded in the notes include:

- Opacity validation in **logical models**.
- **Opacity quantification** and information leakage risk in **probabilistic models**.
- Decidability and complexity results.
- Existing verification tools and whether they also support quantification.
- Applications in discrete event systems and future research directions.

Logical models usually answer whether the system is opaque; probabilistic models quantify **information leakage risk**.

### Basic Notation

The automaton notation used in the manuscript is

$$
G=(X,E,f,X_0).
$$

- $X$: the state set.
- $E$: the event set.
- $f$: the transition function, extended to event strings.
- $X_0\subseteq X$: the set of possible initial states.
- $\mathcal L(G,i)$: the set of event strings executable from state $i$.
- $\mathcal L(G,X_0)$: the set of event strings executable from some initial state.
- $E_o\subseteq E$: the observable event set.
- $P:E^*\to E_o^*$: the natural projection that erases unobservable events.

If $P(t)=P(t')$, the intruder cannot distinguish event strings $t$ and $t'$ through observation. The symbol $\varepsilon$ denotes the empty string.

Opacity definitions are mainly divided into **language-based opacity** and **state-based opacity**.

### Language-Based Opacity

Language-Based Opacity (LBO), also called trace-based opacity, represents secrets as a set of event strings rather than as individual states.

The notes mention work by [Badouel et al. (2007)](https://doi.org/10.1007/s10626-007-0020-5), [Dubreil et al. (2008)](https://doi.org/10.1109/WODES.2008.4605918), and [Lin (2011)](https://doi.org/10.1016/j.automatica.2011.01.002). Lin's formulation uses two sublanguages.
Let

$$
L_S\subseteq\mathcal L(G,X_0),\qquad
L_{NS}\subseteq\mathcal L(G,X_0)
$$

denote the secret and non-secret languages, respectively.

#### Strong Opacity

The system satisfies strong LBO if and only if

$$
\forall t\in L_S,\quad
\exists t'\in L_{NS}:\quad P(t)=P(t').
$$

Equivalently,

$$
L_S\subseteq P^{-1}\bigl(P(L_{NS})\bigr),
$$

or

$$
P(L_S)\subseteq P(L_{NS}).
$$

Every secret string therefore has a non-secret string with the same observation. Unless otherwise qualified, LBO usually refers to this strong version.

#### Weak Opacity

The system satisfies weak LBO if and only if

$$
\exists t\in L_S,\quad
\exists t'\in L_{NS}:\quad P(t)=P(t').
$$

Equivalently,

$$
L_S\cap P^{-1}\bigl(P(L_{NS})\bigr)\ne\varnothing.
$$

The weak version requires only one secret string to have a non-secret cover. It does not ensure protection for all secret behaviors.

#### No Opacity

The manuscript labels the following case “no opacity”:

$$
L_S\cap P^{-1}\bigl(P(L_{NS})\bigr)=\varnothing.
$$

No secret string then shares an observation with a non-secret string.

#### Example: The Choice of Secret Language Matters

The automaton in the manuscript has initial state $0$ and the following transitions:

![Automaton with initial state 0, transitions labeled a, b, and d, and a c self-loop on state 2.](/opacity-lbo-automaton.svg)

Take $E_o=\{a,b,c\}$, so that $d$ is unobservable. For

$$
L_S=\{abd\},\qquad
L_{NS}=\{abc^nd\mid n\ge0\}\cup\{adb\},
$$

we have

$$
P(abd)=ab=P(adb).
$$

LBO holds because the secret string $abd$ has the non-secret cover $adb$.

If instead

$$
L_S=\{abcd\},\qquad
L_{NS}=\{adb,abd\}\cup\{abc^nd\mid n\ge2\},
$$

then

$$
P(abcd)=abc,\qquad P(adb)=P(abd)=ab.
$$

The remaining non-secret strings have observations $abc^n$ with $n\ge2$, which also differ from $abc$. LBO therefore fails.

The same automaton and observation projection can yield different results for different secret and non-secret languages.

> In the second example on manuscript page 4, the written non-secret language conflicts with the subsequent observation calculation. Following the later $abcc^*$ calculation, the example above uses strings containing at least two occurrences of $c$. If the non-secret language included $abcd$, that string would cover itself, and the intended counterexample would fail.

### State-Based Opacity

State-Based Opacity (SBO) represents secrets through states, initial states, or combinations of initial and final states.

#### Current-State Opacity

Current-State Opacity (CSO) protects the information that the system is currently in a secret state.

Let $X_S\subseteq X$ be the secret state set and $X_{NS}\subseteq X$ the non-secret state set. Every execution reaching a secret state must have an execution with the same observation that reaches a non-secret state:

$$
\begin{aligned}
&\forall i\in X_0,\ \forall t\in\mathcal L(G,i),\quad
f(i,t)\in X_S\\
&\qquad\Longrightarrow
\exists j\in X_0,\ \exists t'\in\mathcal L(G,j):\\
&\qquad\qquad f(j,t')\in X_{NS}\ \land\ P(t)=P(t').
\end{aligned}
$$

The alternative execution may start from another initial state. Its observation must be identical, and its final state must be non-secret.

The manuscript also mentions **always opacity / total opacity**: requiring the corresponding current-state opacity at every visited state over a considered set of runs. It does not formalize this concept further.

**Example.** The initial state is $0$, with transitions

![Automaton with initial state 0 and two branches: a then b reaches state 3; c then b reaches state 4.](/opacity-cso-automaton.svg)

Let $X_S=\{3\}$; all other states are non-secret.

- If $E_o=\{b\}$, then $P(ab)=P(cb)=b$. The execution reaching secret state $3$ is covered by the execution reaching non-secret state $4$, so CSO holds.
- If $E_o=\{a,b\}$, observing $ab$ identifies state $3$, so CSO fails.

Opacity thus also depends on the intruder's observability.

#### Initial-State Opacity

Initial-State Opacity (ISO) protects the information that the system started from a secret state.

Here $X_S$ and $X_{NS}$ denote the secret and non-secret initial state sets being compared. The definition is

$$
\forall i\in X_S,\ \forall t\in\mathcal L(G,i),\quad
\exists j\in X_{NS},\ \exists t'\in\mathcal L(G,j):\quad
P(t)=P(t').
$$

Every observation produced from a secret initial state must also be producible from some non-secret initial state.

**Example.** The manuscript gives the following transitions, where $\tau$ is unobservable and $E_o=\{a,b\}$:

![Initial-state opacity automaton with an a self-loop on state 0, unobservable tau transitions, and all transitions from the manuscript.](/opacity-iso-automaton.svg)

If state $2$ is the secret initial state and $0$ is an allowed non-secret initial state, every execution from $2$ is covered by an execution from $0$ that first takes the unobservable $\tau$ transition to $2$ and then follows the same execution. ISO holds for the initial state sets compared in the manuscript.

If initial state $0$ is instead secret, the observation $aa$ can only arise from an execution starting at $0$. Other states cannot produce two consecutive occurrences of $a$ without an observable $b$. ISO therefore fails when the other states are the non-secret initial states.

> This example compares multiple possible initial states. The initial arrow pointing to $0$ in the drawing cannot be interpreted as allowing only $0$ as an initial state; that interpretation would exclude the secret executions starting from $2$ used in the notes.

#### Initial-and-Final-State Opacity

Initial-and-Final-State Opacity (IFO) protects combinations of initial and final states. The manuscript associates this concept with [Wu and Lafortune (2013)](https://doi.org/10.1007/s10626-012-0145-z).

Let the secret and non-secret state-pair sets be

$$
X_{SP}\subseteq X_0\times X,\qquad
X_{NSP}\subseteq X_0\times X.
$$

The definition is

$$
\begin{aligned}
&\forall (x_0,x_f)\in X_{SP},\quad
\forall t\in\mathcal L(G,x_0),\quad f(x_0,t)=x_f\\
&\qquad\Longrightarrow
\exists (x_0',x_f')\in X_{NSP},\quad
\exists t'\in\mathcal L(G,x_0'):\\
&\qquad\qquad f(x_0',t')=x_f'\ \land\ P(t)=P(t').
\end{aligned}
$$

The alternative string $t'$ must start from the alternative initial state $x_0'$. The manuscript omits the prime at the corresponding location; it has been made consistent here.

ISO and CSO can be viewed as special cases of IFO:

- Setting $X_{SP}=X_S\times X$ and $X_{NSP}=X_{NS}\times X$, where $X_S,X_{NS}\subseteq X_0$, restricts only the initial state and yields ISO.
- Setting $X_{SP}=X_0\times X_S$ and $X_{NSP}=X_0\times X_{NS}$ restricts only the final state and yields CSO.

### Verifying and Ensuring Opacity

Given a system $G$, a secret, and the intruder's observation mechanism, two questions arise: **does the system satisfy the required opacity property, and, if it does not, how can it be made to satisfy that property?**

The manuscript identifies three main approaches:

| Approach | Purpose | Description in the manuscript |
| --- | --- | --- |
| Verification | Determine whether the system satisfies opacity | Model checking of opacity properties |
| Supervisory Control Theory (SCT) | Restrict system behavior to protect secrets | Constrain possible system behaviors to preserve opacity |
| Enforcement | Ensure opacity between observation inputs and outputs | The manuscript stops after “input observable events, output modified information” |

#### 4.1 Verification

opacity verification $\iff$ **universality problem**, this is stated by [Cassez, Dubreil & Marchand, 2012](https://doi.org/10.1007/s10703-012-0141-9).

Also, by **encoding the opacity properties**, the solutions can be reduced to **classical model-checking approaches and tools.**

#### 4.2 SCT

The core problem is construct specific types of **supervisor**. Supervisor is used to controll the controllable events to protect the secrets.

Mathematical definition is not mentioned in this review.

#### 4.3 Enforcement(non-intrusive)

There are three main approaches:

- deleting occurrences of events from the output;
- adding events to output;
- **delaying** the output;

Mathematical definition is also not mentioned in this review.
